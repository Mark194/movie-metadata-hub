# Архитектура онлайн-кинотеатра "Movie Metadata Hub"

## Общий обзор

Система представляет собой микросервисную платформу для управления контентом, пользователями и подписками. Каждый сервис выполняет строго определённую функцию, взаимодействуя через REST API (синхронно) и очередь задач (асинхронно через Celery). Развёртывание осуществляется в контейнерах Docker с оркестрацией через Docker Compose (или Kubernetes в перспективе).

## Описание микросервисов

### Auth Service

Ответственность:
- Регистрация, аутентификация (JWT), управление ролями и разрешениями.
- Хранение пользовательских учётных записей, хэшей паролей.
- Управление чёрным списком токенов (Redis)
- Предоставление данных о пользователях для других сервисов через внутренние эндпоинты (/internal/users).

Технологии: FastAPI, SQLAlchemy (async), PostgreSQL, Redis, JWT, Python-jose.

API: /api/v1/auth/* (публичные), /api/v1/internal/* (внутренние для других сервисов).

### Film Service (fast api)

Ответственность:
- Предоставление данных о фильмах, персонах, жанрах.
- Поиск и фильтрация через Elasticsearch.
- Проверка статуса подписки пользователя через запрос к Billing (для отображения контента).

Технологии: FastAPI, Elasticsearch, PostgreSQL (кэш метаданных), Redis (кэш запросов).

Зависимости: Auth (проверка JWT).

### Admin Service

Ответственность:
- Интерфейс для администраторов (CRUD фильмов, персоналий, жанров).
- Управление промокодами и подписками (через Billing API).
- Просмотр профилей пользователей (если будет реализован сервис профилей).

Технологии: FastAPI (бэкенд), React/Vue (фронтенд), интеграция с другими сервисами через REST.

Зависимости: Auth (проверка ролей), Billing, Notifier (уведомления админов).

### Notifier Service

Ответственность:
- Отправка уведомлений по email, SMS, push.
- Шаблонизация сообщений (Jinja2).
- Обработка событий от других сервисов (регистрация, подписка, истечение триала).

Технологии: FastAPI, Celery, Redis (очередь), шаблонизация.

Зависимости: Auth (для данных пользователя), внешние провайдеры.

### Billing Service

Ответственность:
- Управление промокодами (создание, валидация, применение, генерация).
- Обработка платежей (интеграция с платёжным шлюзом).
- Управление подписками (активация, продление, истечение).
- Отслеживание статусов применений и причин отказов.
- Административные эндпоинты для ручного управления (создание промокодов, применение к пользователю).

Технологии: FastAPI (async), SQLAlchemy, PostgreSQL, Celery (задачи на активацию/истечение подписок), Redis (кэш).

Зависимости: Auth (JWT, проверка ролей), Notifier (уведомления), Payment Gateway (внешний).

## Общие компоненты

### PostgreSQL

- Назначение: основное реляционное хранилище для всех сервисов (каждый сервис имеет свою схему или отдельную БД).
- Репликация: мастер-слейв для чтения (опционально).
- Миграции: Alembic для каждого сервиса.

### Elasticsearch

- Назначение: полнотекстовый поиск по фильмам, персонам, жанрам. Аналитика (популярные фильмы, рекомендации).

- Индексы: movies, persons, genres.

### Redis
- Назначение: кэширование (данные фильмов, сессии, JWT blacklist), брокер для Celery.

- Кластер: одна нода (в продакшене – кластер с репликами).

### Celery + Redis Broker
- Назначение: асинхронная обработка задач (отправка уведомлений, активация подписок).
- Воркеры: отдельные для разных очередей (email, sms, billing).

## Взаимодействие между сервисами

### Синхронное (REST)

- Основной API → Auth: проверка JWT (встроенная логика, без внешнего вызова) – но можно использовать внутренний запрос для получения ролей.

- Основной API → Billing: получение статуса подписки пользователя (для отображения премиум-контента).

- Admin → Billing: управление промокодами, просмотр подписок.

- Billing → Auth: обновление статуса is_premium через внутренний эндпоинт.

- Billing → Payment Gateway: инициализация платежа.

### Асинхронное (Celery)

Billing → Notifier: отправка уведомления при активации/окончании подписки.

Billing → celery tasks: активация подписки, обновление статуса в auth.


## Развёртывание

### Docker Compose

Для разработки и небольших нагрузок используется docker-compose.yml с контейнерами:
- theatre-db (PostgreSQL)
- redis
- elasticsearch
- auth
- fastapi
- admin
- notifier
- billing
- jaeger
- celery-worker (общий воркер для всех задач, или несколько очередей)

## Безопасность

- JWT с коротким временем жизни, обновление через refresh-токен.

- HTTPS обязателен для всех внешних соединений.

- Внутренние токены для межсервисного взаимодействия (в заголовке X-Internal-Token).

- Роли и разрешения: строгое разграничение, административные эндпоинты защищены require_permission.

- Шифрование чувствительных данных в БД.

## Масштабируемость и отказоустойчивость

- Горизонтальное масштабирование: каждый сервис может иметь несколько реплик.

- Кэширование: Redis для снижения нагрузки на БД.

- Очереди: Celery с приоритетами и повторными попытками.

- Репликация БД: мастер-слейв для чтения.

- Healthchecks в Docker-контейнерах для автоматического перезапуска.
